Column and layer order is not negotiable: `contract → api-client → api → features → entities → pages
→ route → nav → mocks → state-plan row`. The layer gate (`pnpm quality:layers`) may only pass in that
order, so working out of order means rewriting.

**Notifications need no step at all (AIS-136).** The toast stack and the log drawer are mounted once,
by `<NotificationHost />` in `app/layout/AdminLayout.tsx`, and the capture adapters are bound to the
single store in `main.tsx`. A page therefore never mounts `NotificationProvider` / `NotificationHost`,
never creates a notification store and never sets `meta.successMessage` on its mutations: the global
capture already toasts every `banner`/`page` failure and logs every `field` one. The only two things a
page may do are (a) pass `useNotifier()` + a `successMessage` into `useAppForm` for a successful write,
and (b) render its own error region for the tier it owns. The public `/login` route deliberately has
no host.

**The standard list (AIS-174, step 11).** `DataTable` with its `isLoading` skeleton and the `sr-only`
loading sentence, `Pagination` fed by `meta.pagination`, and `EmptyState` with copy only. The create
entry point is the **header action** — a link, see step 12 — and the empty state deliberately carries
**no** action button: two competing "create" affordances on an empty list is one too many.

Two **documented gaps, not defects**: there is no search/filter UI (`useListParams` parses the `search`
parameter, no page exposes it yet), and there is no per-row icon action (the row's name is the link into
the read-only overlay). A page that needs either opens its own ticket; a page that silently "fixes" one
is a defect.

**Where a route path comes from (AIS-174, step 12).** One literal, N consumers — and the owner is
decided by the layer, not by taste:

1. **List and other static paths** live in [`app.const.ts`](../../apps/admin/src/app/app.const.ts:38)
   (`APP_ROUTE_API_KEYS_PATH`, `APP_ROUTE_CALLS_PATH`, …), because the navigation and the breadcrumb
   both read them and both live in `app/`.
2. **Every page-owned path** — the create overlay (`API_KEYS_CREATE_ROUTE_PATH`) and the detail/overlay
   templates (`API_KEY_VIEW_ROUTE_PATH`, `API_KEY_EDIT_ROUTE_PATH`) — lives in the page const
   ([`api-keys.const.ts`](../../apps/admin/src/pages/api-keys/api-keys.const.ts:24)). The page builds the
   row link and the header action, and `pages/` may not import `app/` (`no-page-to-higher-layer`).
3. The registry mounts **the same exported constant**; a hand-retyped path in either place is a defect.
4. The `PageShell` `back` slot takes its URL from the page const too, because the primitive is
   router-free and the page owns every `Link`.

The step-12 row's "except a detail route" is the shorthand of rule 2: it covers the overlay children as
well, not only a `:identifier` route.

## 3. Do not

| Do not                                                                         | Do instead                                                                                                                                                             |
| ------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Call `fetch` outside `packages/api-client`                                     | a service method, consumed by a hook                                                                                                                                   |
| Copy server data into a store or `useState`                                    | read it from the TanStack Query cache                                                                                                                                  |
| Branch on `error.status` / `error.code` / `instanceof ApiError` in a component | `toErrorSurface` / `toFieldErrors` in a `*.logic.ts`                                                                                                                   |
| Use a colour literal, a Tailwind palette utility or an arbitrary colour value  | `packages/ui` tokens and primitives                                                                                                                                    |
| Call `useForm` directly in a page                                              | `useAppForm`                                                                                                                                                           |
| Import another page's module or store                                          | share through `entities/` or `lib/`                                                                                                                                    |
| Import `app/` from `pages/`                                                    | keep the route path in the page const or `app/app.const.ts`                                                                                                            |
| Add a second navigation list                                                   | the `route-registry.tsx` entry is the only list                                                                                                                        |
| Duplicate validation copy                                                      | the shared catalogue in `packages/shared`                                                                                                                              |
| Mount `NotificationProvider` / `NotificationHost` on a page                    | the host already lives in `AdminLayout`, once                                                                                                                          |
| Create a notification store, or set `meta.successMessage` on a write           | one store in `app/notifications`, the form's `notify` port                                                                                                             |
| Render the create/edit form inline under the list                              | a nested route + `EntityDialog` (step 12b, AIS-155)                                                                                                                    |
| Keep “is the dialog open” in `useState` or a store                             | the URL is the state; close with `useEntityDialog` — exception: a confirmation that is not navigable (no link, no reload) keeps its open flag in local state (AIS-173) |
| Call `history.back()` to close an overlay                                      | `navigate(listPath, { replace: true })`                                                                                                                                |

**Documented exceptions (AIS-174).** Four surfaces do not follow the page-folder + `PageShell` pattern.
They are listed here so the exception is a decision and not a gap, and so a future page knows when its
own exception ends:

| Surface                                                                                   | Why it is the exception                                                                                                                                                      | Ends when                                                                           |
| ----------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------- |
| [`LoginPage.tsx`](../../apps/admin/src/pages/LoginPage.tsx:9)                             | renders **outside** `AdminLayout` (`ProtectedRoute` centres its `Card`) and its heading is `text-xl`, not the shell's `text-2xl` — the shared frame would fight the centring | the real authentication page lands (cookie session); it then becomes `pages/login/` |
| [`PlaceholderPage.tsx`](../../apps/admin/src/pages/PlaceholderPage.tsx:18)                | static landing page: no data, no state, one footer — the shell is all it needs, a folder would only add an empty `ui/`                                                       | the first real dashboard replaces it                                                |
| [`NotFoundPage.tsx`](../../apps/admin/src/pages/not-found/NotFoundPage.tsx:1)             | the catch-all has **no trail** (its `breadcrumbLabel` is `null`, the only legal value there) and is not linked from the nav                                                  | never — it is the permanent fallback                                                |
| [`CallsPlaceholderPage.tsx`](../../apps/admin/src/pages/calls/CallsPlaceholderPage.tsx:1) | placeholder for a feature that has not started; the surface is already a page folder with its own const                                                                      | the real call list lands                                                            |

A flat exception file keeps its copy **in the page module**, as exported constants: the layer gate's
`no-flat-page-to-page` rule forbids a flat page from importing anything under `src/pages/`, so a sibling
`*.const.ts` would be unreachable for it — and the sibling would itself count as a page. Nothing else is
allowed either: no `*.logic.ts`, no `ui/`, no store outside a page folder. `LoginPage` /
`PlaceholderPage` use exactly that shape, their `*.test.tsx` sits next to them, and the test imports the
page's own constants so the copy keeps one home.

## 4. Done signal

```bash
pnpm quality          # layers + dead code + tokens + field errors + docs
pnpm test:quality     # the gates' own positive/negative fixtures
pnpm typecheck && pnpm -r build && pnpm -r lint && pnpm test
```

A page is done when all of the above are green, the §2 steps exist, and the state-plan row in
`UI-Architecture.md` §5 describes the page.

**What the gate checks.** `pnpm quality:docs` fails when (R1) a relative link in `docs/Specs` points
at a path that does not exist, (R2) a `§N` reference on a line that links a document names a section
that document does not have, (R3) a `docs/Specs` document lacks `**Utolsó frissítés:** YYYY-MM-DD`, or
(R4) one of the pointer documents — this file's §5 list, the rule file's §12, `UI-Architecture.md` §6
and `Admin-Data-Flow.md` §3 — stops linking back here. `docs/Specs/outdated/` is never scanned.

**What it does not check.** Whether a reference is _semantically_ the right section, and a bare `§N`
in prose with no link on the line (its target document is ambiguous). R2 applies to the documents of
this process — this file, `UI-Architecture.md`, `Admin-Data-Flow.md`, `Forms-and-Validation.md` and
`API-Convention.md`; the older operational runbooks keep their own numbering and are out of scope.
