## Notes / deviations

| #   | Topic                     | Detail                                                                                                                                                                                                                       |
| --- | ------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1   | `expires_at` type         | approved as `timestamp with time zone` (nullable) instead of the ticket's `date`: an expiry is a moment, not a calendar day                                                                                                  |
| 2   | Migration-file assertions | the spec reads the committed `0002` SQL, so a regenerated-but-unreviewed migration fails the test suite. The `CREATE SCHEMA` check is `^`-anchored, because a plain `not.toContain` also matched the explanatory SQL comment |
| 3   | `updated_at`              | maintained by Drizzle's `$onUpdate` only; no DB trigger (documented as a deferred follow-up)                                                                                                                                 |
| 4   | `api_key` storage         | the token value is stored as-is (ticket scope); hashing/rotation is a follow-up, not silently ignored                                                                                                                        |
| 5   | Docker CLI                | `docker exec -T …` is rejected in this environment (`unknown shorthand flag: 'T'`); the plain form was used                                                                                                                  |
