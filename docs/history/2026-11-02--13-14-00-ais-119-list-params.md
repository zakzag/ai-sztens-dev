# AIS-119 — URL-owned list state (`useListParams`)

**Date:** 2026-11-02 13:14 (Europe/Budapest)
**Ticket:** AIS-119 — subtask of AIS-105 (admin app foundation & quality gate)
**Plan:** [`docs/plans/2026-10-31--01-40-00-ais-119-list-params-plan.md`](../plans/2026-10-31--01-40-00-ais-119-list-params-plan.md)

## What changed

- New `apps/admin/src/features/api/` folder — the generic, resource-agnostic home for
  cross-cutting list/API helpers (distinct from the `api-keys`-specific `features/api-keys/`).
- [`use-list-params.ts`](../../apps/admin/src/features/api/use-list-params.ts) — `useListParams(schema)`
  reads the typed list query from the URL (`useSearchParams`) and writes changes back,
  defaults omitted, page reset to 1 on any non-`page` change, invalid values silently
  falling back to their schema default.
- [`use-list-params.logic.ts`](../../apps/admin/src/features/api/use-list-params.logic.ts) — the pure
  rules (`parseListParams`, `parseListParamsDefaults`, `toListParamsDefaults`, `applyPageReset`,
  `toListParamsUrlSearchParams`) plus the `ListParamsError` class for the impossible
  no-defaults case.
- [`use-list-params.interface.ts`](../../apps/admin/src/features/api/use-list-params.interface.ts) and
  [`use-list-params.const.ts`](../../apps/admin/src/features/api/use-list-params.const.ts) — types and
  literals, separated per the TS rules.
- [`app-router.mock.tsx`](../../apps/admin/src/test/mocks/app-router.mock.tsx) — new
  `renderHookWithRouter` helper (MemoryRouter + a `useLocation` probe exposing `getSearch()`),
  so hook tests can assert the URL the hook actually wrote.
- Two test files: 13 pure-logic tests + 7 hook tests (parse fallback, defaults omitted, page
  reset, invalid `setParam` fallback, `resetParams`, resource `sort` via `createListQuerySchema`).
