# `qa:all` — one command for the whole definition of done

**Date:** 2026-11-04 16:09 (Europe/Budapest)
**No Jira ticket** (developer tooling; the board tracks product work)

## Why

The AIS-113 work needed five commands to prove itself — `pnpm build`, `pnpm -r lint` (`lint`),
`pnpm quality`, `pnpm test`, plus the gate/script self-tests — and the same list is spelled out in
three documents (`UI-Architecture.md` §9, the git-hooks plan, the AIS-105 audit). Running them by
hand is how a gate silently gets skipped. `pnpm qa:all` makes the list executable.

## What changed

| File                                                             | Change                                                                          |
| ---------------------------------------------------------------- | ------------------------------------------------------------------------------- |
| [`package.json`](../../package.json:1)                           | new root script `qa:all`                                                        |
| [`docs/Specs/UI-Architecture.md`](../Specs/UI-Architecture.md:1) | §9 documents the command and says why it is not wired into `prepare`/pre-commit |

```json
"qa:all": "pnpm quality && pnpm test:quality && pnpm sonar:test && pnpm test:agents && pnpm build && pnpm lint && pnpm test"
```

Order is deliberate — **cheapest gate first**, so a static rule violation fails in ~10 seconds
instead of after a five-minute test run:

1. `pnpm quality` — dependency-cruiser layers → knip dead code → palette → field-error rules.
2. `pnpm test:quality` — the gates' own tests (negative + positive fixtures).
3. `pnpm sonar:test` — `scripts/sonar/*` unit tests.
4. `pnpm test:agents` — `scripts/lib/agent-artifacts/*` tests.
5. `pnpm build` — `pnpm -r build`, all six projects (`tsc`/`nest build`/`vite build`).
6. `pnpm lint` — `pnpm -r lint` (web, admin, api).
7. `pnpm test` — the five unit suites (shared → api-client → ui → admin → api).

`&&` (not `;`) on purpose: the first red step stops the run, so the output ends on the actual cause.

## Verification

```powershell
pnpm qa:all   # exit 0
```

Observed on this tree: gates `0 violations` / `no dependency violations`, `build: Done` for all six
projects, `lint: Done` for all three apps, tests `335 + 198 + 30 files (349) + 29 files (433) + api`
all green.

## Notes / limits

- It does **not** run `pnpm test:e2e` (needs a Postgres service) or `pnpm test:stack` (needs the
  Docker stack); those stay CI/smoke-only.
- It does **not** run `pnpm format:check` — that is still red repo-wide on pre-existing markdown
  drift; formatting rules apply per touched file until the git-hooks plan lands.
- Not hooked into `pre-commit`/`pre-push`: minutes-long by design. The fast subset belongs to the
  git-hooks quality gate (plan `2026-10-27--11-41-38-git-hooks-quality-gate-plan.md`).
