## 3. Where the ticket text was overruled

Four things in the ticket predate later decisions; the screen contract won in each case and the
deviations are recorded on the ticket:

1. the **responsible-operator filter** the ticket asks for no longer exists (AIS-189 removed the

2. the **client service** is not this ticket's work — AIS-178 delivered it, so only the
   composition-root line was added;
3. `use-customers.ts` is named **`use-customers-list.ts`** (spec §10 and UI-Architecture §5);
4. the `UI-Architecture` §5 row already existed — what AIS-19 changed is the **§7 `zustand` row**
   (`planned → installed`).

## 4. Decisions worth remembering

- **One interaction, one URL write.** Sort sends a `{ sort, order }` patch through `setParams`,
  reset sends all four defaults in one call; `page` is reset by the hook, not by the caller.
- **Two empty-state copies.** `hasActiveFilters` picks “create the first one” vs “clear the
  filters” — asking for a new customer while a filter hides a hundred rows would be a lie.
- **The search field is local state, the term is URL state.** The input keeps its own text and
  writes the settled value after 300 ms, so typing does not create one history entry per keystroke.
- **The store is a vanilla factory, created once per mount.** Forms cannot carry a value across
  steps (RHF seeds `defaultValues` on mount only); nothing is persisted, so a draft never
  resurrects next to a fresh `?step=1`.
