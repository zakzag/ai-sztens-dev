# AIS-120 — MSW test harness (milestone)

## 1. Problem / feature

The admin SPA hook/form tests mocked the **service module**
(`vi.mock('services/api-client')`), so the `httpClient`, the envelope unwrap
([`envelope.logic.ts`](../../packages/api-client/src/envelope.logic.ts:1)) and the
`ApiError` construction never ran in those tests. A service-signature change could
silently produce “green” tests that proved nothing.

## 2. Measured data / evidence

- Before: [`use-api-keys.test.tsx`](../../apps/admin/src/features/api-keys/use-api-keys.test.tsx:50)
  and [`ApiKeyForm.test.tsx`](../../apps/admin/src/pages/api-keys/ui/ApiKeyForm.test.tsx:49)
  both `vi.mock`ed the composition root; `msw` present in **0** package.json files.
- After: `pnpm --filter @callback/admin test` → **23 files / 195 tests pass**;
  `msw` installed as `^2.15.0`.

## 3. Root cause / design rationale

Mocking at the service boundary throws away the two layers the tests are meant to
guard (transport + envelope). The chosen mock point is the **network** (MSW), so
the real client runs and only `fetch` is replaced. Two non-obvious decisions:

- **D-URL:** the transport calls a relative `/api/api-keys`; jsdom cannot resolve
  it, so `VITE_API_BASE_URL` is pinned absolute in `vitest.config.ts` test env.
- **D-LISTEN:** the composition root captures `globalThis.fetch` at import time;
  MSW patches it on `listen()`. `listen()` therefore runs at **module scope** of
  the setup file (before test imports), not in `beforeAll`.

## 4. Solution / implementation

| File | Change |
|---|---|
| `apps/admin/package.json` | add `msw@^2.15.0` |
| `apps/admin/vitest.config.ts` | absolute `VITE_API_BASE_URL` in `test.env` |
| `apps/admin/src/test/setup.ts` | module-scope `server.listen()`, reset/close lifecycle |
| `apps/admin/src/test/mocks/server.ts` | shared `setupServer` |
| `apps/admin/src/test/mocks/handlers/handler-envelope.ts` | `successResponse`/`errorResponse` over shared envelope factories |
| `apps/admin/src/test/mocks/handlers/api-keys.handlers.ts` | 14 api-keys handlers |
| `apps/admin/src/test/mocks/handlers/generic.handlers.ts` | `anyUrl*` wildcard handlers |
| `apps/admin/src/test/mocks/render-with-providers.tsx` | QueryClient + Session + MemoryRouter |
| `apps/admin/src/test/mocks/request-recorder.ts` | MSW `server.events` request recorder |
| `packages/shared/.../api-keys.fixture.ts` + `index.ts` | `FILLED_API_KEY`, `SECOND_API_KEY`, `VALID_API_KEY_PAIR` |
| deleted | `apps/admin/src/test/mocks/api-keys.mock.ts` (service double) |
| migrated | `use-api-keys`, `ApiKeyForm`, `ApiKeysTable`, `api-key.mapper` tests; new `use-api-keys.envelope.test.tsx` |
| `docs/Specs/UI-Architecture.md` | `test/mocks` layer + `msw` dependency rows |

## 5. Outcome and how to verify

- No `vi.mock('services/api-client')` remains in hook/form tests; the
  `UNEXPECTED_PAYLOAD` test proves the envelope unwrap really runs.
- Verify: `pnpm --filter @callback/admin test` (all green),
  `pnpm --filter @callback/admin lint`, `pnpm --filter @callback/shared build`.
