# Milestone — appearance selector becomes a select box (AIS-149)

## Problem / feature

AIS-148 replaced the header's radio-group appearance selector with a `Combobox`. That turned a
three-item choice into a search field: the closed control showed the selection as _text_, opening
it emptied the text, closing it restored it. The requirement was a **plain select box** — closed
it shows the chosen appearance **with its icon**, open it lists the three appearances, each with
its icon, and there is **nothing to search**.

## Measured data / evidence

The primitive decides the shape of the solution: `Combobox` filters its list with
`filterOptions(options, inputValue)`. With the selection pre-filled in the input, opening the
control produced exactly **one** option:

```text
× opens the three appearances on focus and marks the selected one
  → expected [ 'Sötét' ] to deeply equal [ 'Világos', 'Sötét', 'Ambient' ]
```

AIS-148 worked around it with two new ports (`onOpen` cleared the text, `onClose` restored the
label). Correct, but three moving parts for a three-item choice.

## Root cause / design rationale

- **A select has no text**, so the "text is a filter, not a value" problem disappears instead of
  being managed. That is why the AIS-148 ports were removed rather than kept "just in case".
- **Alternatives considered.** (a) Native `<select>` — cannot render an SVG in an `<option>`, which
  is a hard requirement here. (b) `DropdownMenu` as-is — a row-action menu, no `aria-checked`
  state for the current choice. (c) New `SelectMenu` primitive on Radix `DropdownMenu` +
  `RadioGroup`/`RadioItem` — chosen: `menuitemradio` semantics, arrow keys, `Escape` and focus
  return come free, and the look reuses the existing button/menu recipes instead of a fourth
  control style.
- **Icons are data** (`icon?: ReactNode`). The icon set marks every SVG `aria-hidden`, so the
  accessible name of an option stays its label, and the trigger is named
  `"<label>: <chosen label>"` to keep the visible text inside the accessible name.

## Outcome and how to verify

The header band holds one button: `🌙 Sötét ⌄`. Clicking opens the three appearances with icons,
the current one `aria-checked`; `Escape`, a click outside, or a pick closes the panel and the
trigger shows the chosen appearance. Nothing is applied to the document, nothing is persisted.

```bash
pnpm --filter @callback/ui test
pnpm --filter @callback/admin test
pnpm --filter @callback/admin typecheck
pnpm quality
```

Manual: `pnpm dev`, open `/api-keys`, click the appearance button — all three rows must be listed
with their icons on the first click (no clearing, no typing), and the trigger must show the picked
appearance immediately after.

## Follow-ups

- `SelectMenu` is menu-based (`role="menu"`), not a listbox: Radix's menu is the right engine for a
  button-triggered popup, but a future mobile-first variant may want a `listbox` instead.
- Ordering and paging are out of scope: the options render in the caller's order, unfiltered.
- The theme is still a UI contract (AIS-140 `D3`): `onThemeChange` remains a documented no-op.
