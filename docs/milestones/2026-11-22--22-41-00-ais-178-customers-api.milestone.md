# Milestone — the `customers` API slice (AIS-178/b)

**Date:** 2026-11-22 · **Ticket:** AIS-178 (subtask of AIS-14) · **Slice:** b of a–f

## 1. Problem

Slice a registered the six `customers` operations in the shared contract but shipped no server side,
so `main` was red: the AIS-110 gate reported `missing-service` for every one of them, and the
`envelope-contract` / `openapi` gates had nothing to prove. The brief was the `apps/api` half:
repository, service, controller, audit — plus the contract corrections the implementation proved
necessary.

## 2. Evidence

```text
before:  api-client service-coverage → 6 × "missing-service" for customers.*
after:   pnpm --filter @callback/api test     → 53 suites / 765 tests passed
         pnpm --filter @callback/api lint      → clean
         pnpm --filter @callback/api typecheck → clean
         customers slice: 8 suites / 129 tests
```

Two pre-existing suites had to change, both because the registry grew (`zod-openapi.spec.ts`) or
because the delete path now reads a pre-image (`customers.controller.spec.ts`). No regression in
`api-keys`, `audit` or `db`.

## 3. Root cause / design rationale

Four constraints drove the shape, and each one closed a failure mode that a naive implementation
would have hidden:

| Constraint | Consequence |
| --- | --- |
| An audit row must not be able to land outside the business write | the **repository** exposes `runInTransaction`, and `AuditWriter.write` takes the `tx` handle — passing the root `Database` does not type-check |
| A unique violation aborts the Postgres transaction | the customer-number retry wraps the **whole** unit of work and runs in a fresh transaction, once |
| `update()` on `updated_at` `$onUpdate` bumps the column even with no fields | an empty `PATCH` short-circuits: no write, no audit row, current row returned |
| `'abc'::uuid` raises `22P02` → `500` | `:id` is validated with the existing `ZodValidationPipe` and a shared `customerIdSchema` → `400` |

Alternatives considered: a `pg_advisory_xact_lock` per month (removes number collisions entirely —
documented, not built); a pre-check `SELECT … WHERE tax_number = …` (lies about the **partial** unique
index, so classification stays on `23505` + constraint name); copying server data into the response
from `RETURNING` (cannot compute the derived columns, so writes re-read the row).

## 4. Solution

New `apps/api/src/customers/` folder: `const`, `interface`, `logic`, `mapper`, `errors`,
`error-guard`, `filter`, `repository.interface`, `repository`, `service`, `controller`, `module`, plus
mocks and one spec per unit. Six routes under `/api/admin/customers`; the four mutating handlers read
`@Req()` for the audit facts.

| Area | File | Change |
| --- | --- | --- |
| SQL | `customers.repository.ts` | page + count in one `Promise.all`; two derived projections as correlated subqueries; four detail round trips; guarded writes; `runInTransaction` |
| Orchestration | `customers.service.ts` | one transaction per write, audit inside it, retry-once allocation, error translation |
| Contract | `packages/shared/.../customers.schema.ts` | `customerIdSchema`; `primaryContactName` on `customerSchema` |
| Contract | `packages/shared/.../customers.contract.ts` | `remove.errors` without `STALE_WRITE` |
| OpenAPI | `apps/api/src/common/openapi/zod-openapi.ts` | six new payload components |
| Wiring | `apps/api/src/app.module.ts` | imports `CustomersModule` (which imports `AuditModule`) |
| Docs | `docs/Specs/API-Convention.md` | new §4.3 |
| Tests | `apps/api/test/customers.e2e-spec.ts` | real-Postgres scenario with audit assertions |

## 5. Outcome and how to verify

- Six routes mounted; `envelope-contract` and `openapi` suites are the runtime proof that the
  controller matches the registry.
- Every accepted mutation writes exactly one ledger row (`insert` / `update` / `update` /
  `soft_delete`), with only the changed keys.
- Both `409` codes are raised from constraint names; a malformed uuid is a `400`; a repeat delete is
  a `404`; archiving frees the tax number.

```powershell
pnpm --filter @callback/shared build
pnpm --filter @callback/api test
pnpm --filter @callback/api lint
pnpm --filter @callback/api typecheck
# e2e (needs DATABASE_URL + pnpm db:up)
pnpm --filter @callback/api test:e2e
```

## 6. Follow-ups

- **Slice c** (`packages/api-client/src/customers/`) is still required to turn the AIS-110 gate green;
  b and c are meant to merge together.
- `api-keys.api-error-guard.ts` could reuse `findPostgresError` — deferred to keep this diff out of a
  shipped feature.
- The e2e writes permanent ledger rows tagged `customers-e2e/1.0 (AIS-178)`; purging them needs a
  superuser session (`session_replication_role = replica`).
- Admin authentication (AIS-73/74) still leaves the actor as `system`, and that period is not
  backfillable.
