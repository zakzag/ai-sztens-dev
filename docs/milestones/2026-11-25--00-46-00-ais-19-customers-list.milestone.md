# AIS-19 — the customer list, and the admin's first page store

**Date:** 2026-11-25 · **Ticket:** AIS-19 (subtask of AIS-15) · **Branch:** `AIS-15-customers-admin`
**Plan:** [`2026-11-25--00-10-00-ais-19-customers-list-plan.md`](../plans/2026-11-25--00-10-00-ais-19-customers-list-plan.md)

## 1. Problem / feature

The customers API, its client service and its screen contract were all delivered (AIS-14/AIS-178,
AIS-17), but `apps/admin` had **no** customer screen: no `pages/customers`, no
`features/customers`, no `entities/customer`. AIS-19 is the first UI slice of the AIS-15 wave and
the change that had to prove the standardised list pattern on a real second resource.

It is also the ticket that closes the two documented gaps of the standard list (AIS-174): a
server-side **search/filter row** and a **per-row action menu**. No page had ever rendered either.

## 3. Design rationale

**One interaction = one URL write.** A sort click changes `sort` *and* `order`, and the page number
must reset. Sending them as two `setParam` calls would rebuild the second URL from the
pre-render query (losing the first change) and add two history entries. `setParams(patch)` is the
only writer, and the page reset stays inside the hook rather than being restated by every caller.

**A page store, and why it is only one field.** The wizard's step lives in the URL (a reload, the
back button and a copied link must all land on the same step), but the values collected in a step
cannot: react-hook-form seeds `defaultValues` on mount only. That single fact is what justifies
installing `zustand`; everything else — list params, the step, the submitted result — stays in the
URL or in TanStack Query. Nothing is persisted: a half-filled draft must not resurrect next to a
fresh `?step=1`.

**Two empty-state messages.** `hasActiveFilters` chooses between “create the first customer” and
“clear the filters”. An empty table has two different causes and two different next steps, and
inviting a create while a filter hides a hundred rows would be actively misleading.

**The search field is local state, the term is URL state.** Typing keeps its own `useState` and
writes the settled value after 300 ms, so one search produces one history entry instead of one per
keystroke — the only place on this page where the two buckets are deliberately split.

**Alternatives rejected:** a `DataTable` with local sorting (contradicts `meta.total`); keeping the
wizard draft in `useState` at the page root (unreachable from the step bodies without prop
drilling, and lost on every step change); a client-side filter over the current page (would have
made the pager lie).

## 5. Outcome and how to verify

`/customers` is reachable from the navigation; the URL carries only `page`, `limit`, `sort`,
`order`, `q`, `type`, `status`, `source`; a copied filtered URL restores the view, and back/forward
work. `/customers/new` renders the wizard shell and step 1 writes into the page store.

```bash
pnpm --filter @callback/admin typecheck          # green
pnpm --filter @callback/admin test               # 672 tests
pnpm --filter @callback/admin build              # tsc + vite
pnpm quality                                     # six gates, 0 violations
node --test scripts/quality/*.test.mjs scripts/lib/vite-build.logic.test.mjs   # 87 pass
```

On this machine the `pnpm test:quality` script itself fails before running anything: it passes
`scripts/quality/*.test.mjs` to `node --test`, and the installed runtime is Node **20.19.2**, which
does not expand the pattern (the repo's engine floor is `>=24.9.0`). The same files enumerated
explicitly pass 87/87, so this is an environment gap, not a red gate.

## 6. Follow-ups

- **Interim dead ends.** `/customers/:id` (AIS-20) and `/customers/:id/edit` (AIS-21) are not
  mounted yet, so the row name link and *Megnyitás* / *Szerkesztés* reach the not-found page on
  this branch. The contract requires all three, and the wave branch merges as a whole.
- **Wizard steps 2–4 and the submit** belong to AIS-182; the shell renders step 1 only.
- The **responsible-operator filter** the AIS-19 ticket text still asks for does not exist (AIS-189
  removed the field, the column and the contract parameter); the ticket comment records this.
- `pnpm test:quality`'s glob form should be made runtime-independent (explicit file list or a Node
  ≥ 21 floor) so the script is not silently unrunnable on an older local Node.
