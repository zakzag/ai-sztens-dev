## 1. A cél egy mondatban

A lista szűrője, rendezése és oldalja **az URL-ben** éljen — így a link másolható, a
vissza/előre gomb működik, és a böngésző előre-hátra navigálása nem veszíti el a szűrést.

**A te dolgod:** egy `useListParams(schema)` hook, ami a `react-router` search paramétereiből
olvassa ki a query-t, és **visszaírja** a URL-be, ha valaki módosítja.

## 2. Amit már megkaptál — ne írd újra

### 2.1 A shared szerződés (AIS-106, ✅ Done)

A `packages/shared/src/contract/` alatt kész van minden, amire a hook **típus** szempontból
szükséges. Importálhatod a `@callback/shared`-ből:

| Import                                        | Mit ad                                                                                                                                              |
| --------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------- |
| `listQuerySchema`                             | a zod séma: `page` (≥1, default 1), `limit` (1…100, default 20), `order` (`asc`/`desc`, default `desc`), `q` (trimelt, max 200, üres → `undefined`) |
| `createListQuerySchema(sortBy, defaultSort?)` | a `sort` mezőt is behozza **enumként** a hívó allow-listjéből                                                                                       |
| `ListQuery`                                   | a `z.infer` típus: `{ page, limit, order, q? }`                                                                                                     |
| `ListQueryDefaults`                           | `{ limit, order, sort? }` — mi számít „default"-nak                                                                                                 |
| `LIST_QUERY_DEFAULTS`                         | `{ limit: 20, order: 'desc' }`                                                                                                                      |
| `toListQueryParams(query, defaults?)`         | a query → `URLSearchParams`, **a defaultokat kihagyva**                                                                                             |
| `mergeListQuery(query, filters)`              | a resource-specifikus szűrők összefésülése; a lapos mezők **mindig** nyernek                                                                        |

> **A `sort` nincs a statikus sémában.** Ha az AIS-119-nek van rendezhető oszlopa, a
> `createListQuerySchema(['name', 'createdAt'])` factoryt használd, ne a statikus sémát. A
> `zod` `ZodType<T, ZodTypeDef, TItem>` alakját **ne** szűkítsd `unknown`-ra, ha a
> `paginatedSchema`-hoz hasonló generikust írsz — a zod `.nullable()` egy extra array
> dimenzióval bővíti az elemet-típust (lásd az AIS-106 milestone-ot).

## 3. Amit meg kell építeni

### 3.1 A hook — `apps/admin/src/features/api/use-list-params.ts`

A ticket által előírt hely és név. A `features/api/` mappa **új** — ma nincs ilyen.

```ts
useListParams(schema) → { params, setParam, resetParams }
```

| Követelmény                                                                            | Konkrétan                                                                              |
| -------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------- |
| A séma a shared `listQuerySchema` (vagy a resource saját `createListQuerySchema(...)`) | a hook **paraméterként** kapja, nem importálja — így több erőforrás is használhatja    |
| Az **érvénytelen** paraméter **defaultra esik**                                        | `?limit=999` → `limit: 20`; `?page=abc` → `page: 1`. **Nem dob, nem üríti az oldalt.** |
| A defaultok **nem kerülnek** az URL-be                                                 | `?page=1` és `?sort=name` (default) nem látszik                                        |
| A `params` a parse-olt query                                                           | típusa a sémából jön (`z.infer`)                                                       |
| A `setParam` egy mezőt módosít                                                         | a `page` módosításakor **1-re áll vissza** (a szűrő megváltozott → az első oldal)      |
| A `resetParams` visszaállít mindent                                                    | a URL-ből **minden** eltűnik (a defaultok maradnak)                                    |
| Az **érvénytelen** URL-paraméter                                                       | **csendben** defaultra esik — **nincs hibaüzenet**, nincs redirect                     |

### 3.2 A megvalósítás kulcsdöntései

| Döntés                            | Ajánlás és miért                                                                                                                                                                                                                                                                                        |
| --------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Hogyan parse-olunk?**           | `Object.fromEntries(searchParams.entries())` → `schema.safeParse(...)`. **NE** `schema.parse(...)` — az dobna egy érvénytelen `?limit=999`-nál, és a DoD kifejezetten a defaultra esést kéri. A `safeParse` hibáját **csendben** elnyeljük.                                                             |
| **A `sort` mező**                 | Ha az `api-keys`-hoz van rendezés, a `createListQuerySchema(['name', 'createdAt'], 'createdAt')` sémát használd. A statikus `listQuerySchema` **nem** tartalmaz `sort`-ot — ha azt használnád, a `sort` paraméter **eltűnne** a URL-ből.                                                                |
| **A `q` átírása**                 | A `q` módosításakor is **1-re** kell állítani a `page`-et.                                                                                                                                                                                                                                              |
| **Mikor írjuk vissza az URL-be?** | A `setParam` **szinkron** írja (a `setSearchParams` hívás azonnali), nem egy `useEffect`-ben — így nincs egy extra render, ahol az URL még ellentmond a state-nek.                                                                                                                                      |
| **A `resetParams`**               | `setSearchParams({}, { replace: true })` — a `replace` fontos: a „szűrők törlése" ne tegyen egy új előre-ugorható bejegyzést a böngésző előzményébe.                                                                                                                                                    |
| **A `params` memoizálása**        | `useMemo`-val a `searchParams.toString()` kulcsra — különben a `useQuery` `queryKey` minden renderben új identitást kapna, és a TanStack Query végtelenül újra-fetchelne.                                                                                                                               |
| **A `queryKey`**                  | Ha a szűrő hatással van a listára, a kulcsnak **tartalmaznia kell** a szűrőt: `['api-keys', 'list', params]`. A jelenlegi `API_KEYS_QUERY_KEYS.list` **statikus** — ezt az AIS-114 módosítja. **Ha módosítod, az `API_KEYS_QUERY_KEYS` egyetlen helyen van definiálva** — oda kell kerülnie, ne inline. |

### 3.3 A hook (opcionális)

A ticket egy **opcionális** Zustand store factoryt is említ a tranziens UI állapothoz (nyitott
drawer, kijelölt sor, oszlopszűrő).

**A te ticketben ne csináld.** Indoklás:

- a `zustand` **nincs telepítve** — a ticket kifejezetten tiltja az új dependency-t;
- az AIS-119 **nem igényel** tranziens UI állapotot;
- a `useState` a komponensen belül marad.

A store factory akkor készüljön el, ha egy oldal **valóban** igényli — és akkor a
`UI-Architecture.md` §7 dependency-táblájába be kell kerülnie.

## 4. A réteg-szabályok — amiket be kell tartani

A [`react.coding-standards.md`](../../.roo/rules/react.coding-standards.md:1) a normatív
szabályzat. A lényeg:

| Szabály                                                                    | Az AIS-119-re                                                                                                                       |
| -------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------- |
| Importok csak lefelé: `app → pages → features → entities → services → lib` | a hook a `features/api/`-ben van → a `pages/` importálhatja; **a `features/` nem importálhat `pages/`-et**                          |
| **Nincs** `fetch` a `features/`-ben                                        | a hook **nem** hívja a service-t közvetlenül — az a `useApiKeysQuery` dolga                                                         |
| **Szerver adat soha nem kerül store-ba**                                   | a query-t a TanStack Query cache tartja, nem a Zustand                                                                              |
| A `useEffect` + `fetch` a komponensben **tiltott**                         | a hook a `useSearchParams`-t használja                                                                                              |
| Névkonvenció                                                               | `use-list-params.ts` (kebab-case), `*.logic.ts` a tiszta függvényeknek, `*.const.ts` a konstansoknak, `*.interface.ts` a típusoknak |
| Exportok                                                                   | **nincs** `export default`; a `features/`-ben **nincs** `export *`                                                                  |
| Minden async UI path: loading / empty / error / success                    | a szűrő komponensnek ezt is mutatnia kell (a `useApiKeysQuery` már adja a `isLoading`/`errorSurface`/`refetch` mezőket)             |
| A `react-hook-form` + `zodResolver` a formokhoz                            | ha a `q` egy **input**, RHF-kell legyen, ne `useState`                                                                              |
| Nincs színliterál, nincs Tailwind paletta-utility                          | csak `packages/ui` primitívek és token-osztályok                                                                                    |

### A tiszta logika külön

A `react.coding-standards.md` szerint a **tiszta** függvények (parse, merge, param-építés) a
`*.logic.ts` fájlban vannak, és **tesztelhetők hook nélkül**. Ez különösen fontos itt: a
parse-fallback logikát (érvénytelen paraméter → default) **hook nélkül** is tudni kell tesztelni.

Javasolt felosztás:

```text
apps/admin/src/features/api/
  use-list-params.ts        ← a hook (a reaktív rész)
  use-list-params.logic.ts  ← a tiszta parse/param-logika
  use-list-params.interface.ts
  use-list-params.const.ts
  use-list-params.test.ts   ← a tiszta logika tesztjei
```
