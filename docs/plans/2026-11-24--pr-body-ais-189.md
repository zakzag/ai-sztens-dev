# AIS-189 — drop the customer responsible operator

> PR body for the `AIS-189-responsible-operator-removal` branch. Kept in `docs/plans/` because the
> repository keeps its PR bodies as artefacts (`2026-11-23--pr-body-ais-178.md` is the precedent).

## What this changes

The customer carried one optional staff reference, `customer.customers.responsible_operator_id`
→ `iam.operators(id)`, plus a `responsibleOperatorId` filter on the list query. The AIS-15 wave plan had
deferred the **filter** (`D-W2`) because no operator-directory operation exists to populate a picker;
the product decision is stronger — **there is no responsible operator at all**, so the field is removed
instead of parked.

Removing it now is cheap: the feature never shipped, no screen can set it, and no environment holds a value.

## Breaking change

`refactor(customers)!` — two public surfaces shrink:

| Surface | Before | After |
| --- | --- | --- |
| `PATCH` / `POST` body | `responsibleOperatorId?: uuid \| null` | **absent**; the schemas are `.strict()`, so a stale client sending it gets a `400` validation envelope, never a silent no-op |
| `GET /admin/customers` query | `responsibleOperatorId=uuid` | **absent**; a bookmarked link does **not** break — the list-query schema strips the unknown key (its own unit test pins this) |
| DB | `responsible_operator_id uuid` + FK, `ON DELETE SET NULL` | **dropped**, `customer.customers` now has zero foreign keys |

## Migration

`apps/api/drizzle/0008_fine_vulture.sql`:

```sql
ALTER TABLE "customer"."customers" DROP CONSTRAINT "customers_responsible_operator_id_operators_id_fk";
ALTER TABLE "customer"."customers" DROP COLUMN "responsible_operator_id";
```

A **new forward migration** rather than an edit of `0005`: `0005` has already run in migrated
environments, and rewriting it would silently desync them. This is the first real run of the `DROP`
in CI (the e2e Postgres job), and the safe pre-check on a live database is:

```sql
SELECT count(*) FROM customer.customers WHERE responsible_operator_id IS NOT NULL;  -- expect 0
```
